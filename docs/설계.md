# QuickLinks 설계

자주 쓰는 폴더·파일·웹 주소를 클릭 한 번으로 여는 Windows 바탕화면 위젯. C++ Win32, ScanReceiver와 같은 방식(MSVC `build.bat`, 직접 그리는 Fluent UI, 외부 라이브러리 없음)으로 만든다.

> 상태: **설계 확정** (2026-10-26). 결정 내용은 맨 아래 7장. 다음은 1단계 개발.

---

## 1. 목표와 범위

| 한다 | 하지 않는다 (지금은) |
| --- | --- |
| 폴더·파일·네트워크 공유 폴더(`\\서버\공유`)·웹 주소(`http(s)://`) 바로가기 | 파일 탐색기 대체(폴더 안 내용 보기) |
| 탐색기·브라우저 주소창에서 끌어다 놓아 추가 | 클라우드 동기화, 여러 PC 간 공유 |
| 접히는 그룹으로 분류, 검색 | 최근 사용 파일 자동 수집 |
| 트레이 상주, 전역 단축키로 불러오기 | 설치 프로그램(단일 exe로 배포) |

핵심 사용 흐름:
1. 탐색기에서 폴더를 위젯에 끌어다 놓는다 → 목록에 추가됨.
2. 위젯의 항목을 클릭 → 탐색기(폴더) 또는 연결 프로그램(파일)으로 열림.
3. 위젯이 다른 창에 가려졌으면 단축키(`Ctrl+Alt+Space` 안)로 앞으로 불러와서 이름 몇 글자 입력 → `Enter`.

## 2. 화면

### 2.1 위젯 창 (기본 260 × 440, 크기 조절 가능)

**확정: B안 — 한 줄 목록 + 접히는 그룹 제목** (2026-10-26, 시안 A 두 줄 목록 / B / C 큰 아이콘 격자 / D 세로 도크 중 선택). 한 화면에 12~15개가 들어가는 촘촘한 목록이고, 그룹은 탭이 아니라 목록 안의 접히는 제목 줄이다.

```
┌──────────────────────────────┐
│ 바로가기            📌  ＋  ✕ │  ← 머리글: 끌어서 이동, 📌 항상 위, ＋ 추가, ✕ 닫기(트레이로 숨김), 우클릭 = 트레이 메뉴
│ ┌──────────────────────────┐ │
│ │ 🔍 검색                   │ │  ← 입력하면 즉시 걸러짐
│ └──────────────────────────┘ │
│ ▾ 업무 · 3                    │  ← 그룹 제목: 클릭하면 접기/펼치기, 개수 표시
│    📁 2026 견적서              │  ← 아이콘(16px) + 표시 이름, 한 줄
│    📁 스캔 받은 파일        ⋯  │     마우스를 올린 줄: 배경 강조 + ⋯(메뉴) 버튼
│    📊 월간 보고서.xlsx         │
│ ▾ 프로젝트 · 2                │
│    📁 NPE 소스                 │
│    📕 요구사항 정의서.pdf       │
│ ▸ 공유 · 4                    │  ← 접힌 그룹
│                              │
│                              │  ← 목록이 비면 안내 + 버튼 (2.6절 빈 목록)
└──────────────────────────────┘
```

- 경로는 줄에 쓰지 않고, 마우스를 올리면 **툴팁**으로 전체 경로를 보여 준다(0.5초 후).
- 경로를 찾을 수 없는 항목: 이름을 흐리게 + 오른쪽에 작은 경고 표시, 툴팁에 "찾을 수 없음".
- 그룹 제목 줄: `▾/▸ 이름 · 개수`. 클릭으로 접기/펼치기, 접힘 상태는 저장. 그룹이 "기본" 하나뿐이면 제목 줄을 숨겨 그냥 목록처럼 보임.
- 검색 중에는 모든 그룹을 펼친 상태로 걸러서 보여 주고(접힘 상태는 바꾸지 않음), 항목이 하나도 안 맞는 그룹은 숨김.
- 테두리 없는 창 + DWM 둥근 모서리·그림자(Windows 11). 작업 표시줄에는 안 나옴(`WS_EX_TOOLWINDOW`), 트레이 아이콘으로 관리.
- 가장자리를 끌어 크기 조절. 위치·크기는 저장해서 다음 실행에 복원. 저장된 위치가 연결 해제된 모니터 밖이면 주 모니터 안으로 옮김.
- 마우스를 올린 줄은 배경 강조, 선택(키보드)은 강조 테두리.
- 목록이 넘치면 직접 그린 얇은 스크롤 막대(휠 스크롤).

### 2.2 조작

| 동작 | 결과 |
| --- | --- |
| 항목 클릭 | 열기 (폴더 → 탐색기, 파일 → 연결 프로그램, URL → 기본 브라우저). **한 번 클릭(기본)/두 번 클릭은 설정에서 선택**. 두 번 클릭 모드에서 한 번 클릭은 선택만 |
| `Ctrl` + 클릭 | **낱개 선택**: 하나씩 선택에 더하고 빼기 (열지 않음) — 2026-10-26 사용자 요청으로 변경. 원래 "파일 위치 열기"였던 것은 `Ctrl+Enter`와 우클릭 메뉴로만 |
| `Shift` + 클릭 / `Shift` + `↑` `↓` | **범위 선택**: 마지막으로 누른 항목(기준점)부터 여기까지 보이는 항목 전부. `Ctrl+Shift` + 클릭은 기존 선택에 범위를 더함 |
| `Ctrl+A` | 보이는 항목 모두 선택 (접힌 그룹·검색에 걸러진 항목은 제외) |
| 여러 개 선택했을 때 | 선택된 항목 아무거나 끌면 전부 함께 이동(사본에 개수 배지). `Enter`·`Delete`·`Ctrl+C`·우클릭 메뉴의 열기·경로 복사·그룹 이동·제거가 전부에 적용(10개 넘게 열 때는 확인). 이름 바꾸기·경로 수정·파일 위치 열기는 메뉴에서 빠짐. 선택 안에서 그냥 클릭하면 그 하나만 남기고 열기, `Esc`는 하나로 되돌림. 보이지 않는 항목은 선택돼 있어도 동작에서 빠짐 |
| 머리글(제목 표시줄) 우클릭 | 트레이 아이콘 우클릭과 같은 메뉴 (2026-10-26 추가) |
| `✕` | 위젯을 트레이로 숨김 (종료는 트레이·머리글 메뉴의 "종료"). 마우스를 올리면 Windows 닫기 버튼처럼 빨강. 원래 `─`였으나 빼기처럼 보인다는 의견으로 변경 |
| 가운데 클릭 | 경로 복사 |
| 우클릭 / `⋯` 버튼 | 메뉴: 열기 · 파일 위치 열기 · 경로 복사 │ 이름 바꾸기 · 경로 수정… · 그룹 이동 ▸ │ 목록에서 제거 (2.6절) |
| 항목 끌기 | 순서 바꾸기. 항목 위쪽 절반 = 그 앞, 아래쪽 절반 = 그 뒤(같은 그룹). **그룹 제목 위 어디든 = 그 그룹으로**: 펼친 그룹은 맨 위, 접힌 그룹은 맨 끝(제목이 강조됨) — 2026-10-26 수정. 그 전에는 제목 위쪽 절반이 "위 그룹의 끝"이라 헷갈렸음 |
| 그룹 제목 클릭 | 접기/펼치기 |
| 그룹 제목 우클릭 | 메뉴: 그룹 이름 바꾸기 · 새 그룹 · 위로/아래로 · 그룹 삭제(안의 항목은 "기본" 그룹으로) |
| 그룹 제목 끌기 | 그룹 순서 바꾸기 (2단계) |
| 탐색기에서 끌어다 놓기 | 추가 (여러 개 한 번에 가능, 이미 있는 경로는 건너뜀). 놓은 위치의 그룹에 들어감 |
| 브라우저 주소창·링크 끌어다 놓기 | URL 추가. 표시 이름은 페이지 제목(브라우저가 함께 보내 주면), 없으면 도메인 |
| `＋` 버튼 | 머리글 아래에 **입력 줄**이 열림: 경로·주소를 붙여넣거나 입력하면 종류를 자동 판별, 옆에 `폴더…`·`파일…` 찾아보기 버튼 (2.6절) |
| `Ctrl+V` | 클립보드의 경로·URL(텍스트 또는 탐색기에서 복사한 파일) 추가 |
| 검색창 입력 | 이름·경로에 포함된 항목만 표시 (한글 초성 검색은 2단계 후보) |
| `↑` `↓` `Enter` `Esc` | 선택 이동(그룹 제목 줄도 거침) · 열기(제목 줄이면 접기/펼치기) · 검색 지우기/위젯 숨기기 |
| `←` `→` | 그룹 접기 / 펼치기 (항목에서 `←`는 그 그룹 제목으로) |
| `Ctrl+Z` / `Ctrl+Y` (`Ctrl+Shift+Z`) | 실행 취소 / 다시 실행 (2026-10-26 사용자 요청으로 추가). 목록 전체 스냅숏 방식, 최근 50번. 대상: 추가·제거·이동·이름 바꾸기·경로 수정·그룹 추가/삭제/순서. 접기·펼치기와 창 설정은 제외. 입력칸에 포커스가 있으면 그 칸의 글자 실행 취소가 우선 |
| `F2` / `Delete` | 줄 안에서 이름 바꾸기 / 목록에서 제거(확인 없이, 위젯 아래쪽에 "실행 취소" 알림 막대) |

"목록에서 제거"는 **바로가기만 지우고 실제 파일은 건드리지 않는다**. 메뉴 문구도 "삭제"가 아니라 "목록에서 제거".

### 2.4 설정 (작은 창 하나)


- `OpenOn`: `single`(한 번 클릭으로 열기) / `double`(두 번 클릭).
- 그룹 한 줄 = `접힘(1)/펼침(0)|그룹 이름`. 0번 그룹은 "기본" 역할(그룹을 삭제하면 안의 항목이 여기로 옮겨짐).
- 항목 한 줄 = `그룹번호|표시 이름|대상`. 화면에는 그룹 순서대로, 그룹 안에서는 번호 순서대로 표시. 표시 이름에 `|`가 들어오면 다른 문자로 바꿈.
- 대상은 **마지막 필드**라서 앞의 `|` 두 개까지만 나눈다 → URL 안에 `|`가 있어도 안전.
- 대상의 종류는 따로 저장하지 않고 읽을 때 판단: `http://`·`https://`로 시작하면 URL, 그 밖은 파일 경로(`file://`는 추가할 때 경로로 바꿈). 다른 스킴(`javascript:`, `ms-settings:` 등)은 추가할 때 거부.
- `GetPrivateProfileString`은 줄 끝 `;` 주석을 값으로 읽으므로 ini에 줄 끝 주석을 쓰지 않는다.
- 순서 = 번호 순. 바꿀 때마다 `[Links]` 섹션을 통째로 다시 씀.
- 저장은 임시 파일에 쓴 뒤 `MoveFileEx(REPLACE_EXISTING)`로 교체 → 저장 중 꺼져도 기존 목록이 남음.
- 표시 이름 기본값 = 경로의 마지막 부분(파일은 확장자 포함). 드라이브 루트는 `D:\` 대신 볼륨 이름(`업무 (D:)`).

### 4.1 그리기

- ScanReceiver와 같이 **목록을 직접 그린다** (ListView 미사용). 모델이 "화면 줄" 배열(`{그룹 제목 | 항목}`)을 만들어 주고, 줄 높이는 고정(항목 32px, 그룹 제목 28px, DPI 배율 적용 — 2.5절)이라 스크롤·히트 테스트가 단순함. 접기/펼치기·검색 때는 이 배열만 다시 만든다.
- 경로 툴팁은 comctl32 툴팁 하나를 마우스 아래 줄에 맞춰 `TTM_NEWTOOLRECT`로 옮겨 씀 (ScanReceiver 상태 칩과 같은 방식).
- 깜빡임 방지: 메모리 DC에 그린 뒤 한 번에 복사. 배경·강조는 GDI+ 안티앨리어싱, 글자는 GDI ClearType(ScanReceiver `DrawButton`과 같은 조합).
- 색은 2.5절 상수만 쓴다. 버튼·호버 처리 코드는 ScanReceiver `main.cpp`에서 **복사해 와서** 쓰되, 미카 위에서는 알파를 맞춰 그려야 하므로 그리기 부분은 고친다(2.5절 미카 구현 메모).
- PerMonitorV2 DPI, `WM_DPICHANGED`에서 글꼴·아이콘 크기 재생성 (개발 PC는 모니터 2대, 세로 모니터가 음수 좌표).

### 4.2 아이콘과 경로 검사 — 느린 작업은 백그라운드

네트워크 경로는 서버가 꺼져 있으면 `GetFileAttributes`·`SHGetFileInfo`가 **수십 초 멈출 수 있다**. 그래서:

1. 화면에는 먼저 확장자 기반 일반 아이콘(`SHGFI_USEFILEATTRIBUTES`, 디스크 접근 없음)을 그린다.
2. 작업 스레드 1개(COM STA 초기화)가 항목별 실제 아이콘(`IShellItemImageFactory`, 16/32px)과 존재 여부를 구해 `PostMessage(WM_APP_ICON)`로 알림 → 그 항목만 다시 그림.
3. 결과는 경로별로 캐시. 위젯이 다시 보일 때와 5분마다 존재 여부만 재검사.
4. URL은 존재 검사를 하지 않는다(네트워크 요청 없음). 아이콘은 기본 브라우저의 아이콘(`AssocQueryString`으로 `http` 연결 프로그램 → 그 exe 아이콘). 사이트별 파비콘은 하지 않음.
5. 열기를 눌렀는데 경로가 없으면 앱이 멈추지 않고 토스트로 "찾을 수 없음 — 목록에서 제거 / 경로 수정" 안내.

### 4.3 끌어다 놓기

- 브라우저 → 위젯: `UniformResourceLocatorW`(URL) 형식을 먼저 보고, 제목은 `FileGroupDescriptorW`의 파일 이름(`<제목>.url`)에서 얻는다. 둘 다 없으면 `CF_UNICODETEXT`가 URL 모양일 때만 받음. Chrome·Edge에서 실제로 무엇을 보내는지는 개발 중 확인.
- 탐색기 → 위젯: `IDropTarget` (`CF_HDROP`). `WM_DROPFILES`보다 손이 가지만 끄는 중에 "놓을 위치" 선을 그릴 수 있고, 목록 안 끌기(순서 바꾸기)와 같은 코드로 처리됨.
- 관리자 권한으로 실행하면 일반 탐색기에서의 드롭이 UIPI로 막힘 → manifest는 `asInvoker`, 설명서에 "관리자 권한으로 실행하지 말 것" 명시.

### 4.4 기타

- 단일 인스턴스: 이름 있는 Mutex. 두 번째 실행은 기존 위젯을 앞으로 불러오고 종료.
- 전역 단축키: `RegisterHotKey`. 실패하면 트레이 토스트로 알리고 설정에서 바꾸게 함.
- 항상 위 끔 상태에서 `Win+D`를 누르면 위젯도 숨는다(일반 창이므로). 바탕화면에 "붙는" 위젯(WorkerW 아래로 넣는 방식)은 Windows 버전마다 동작이 달라 **하지 않는다** → 대신 단축키로 불러오기.

## 5. 테스트 방법

- **마우스·키보드 자동화로 테스트하지 않는다** (사용자가 같은 PC를 쓰는 중, ScreenShot에서 문제가 있었음).

- 직접 눌러 보는 확인(드롭, 끌어서 정렬, 단축키)은 사용자에게 부탁.
